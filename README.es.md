## ⚠️ Descargo de Responsabilidad Médica

> **KENRYU es exclusivamente para Uso en Investigación (RUO).** No sustituye el criterio médico profesional, la evaluación individualizada del paciente, las guías clínicas locales ni la revisión por un profesional de la salud cualificado. La evidencia proviene de bases de datos públicas (NCBI, miRTarBase, TargetScan, STRING-DB) y debe ser verificada rigurosamente antes de cualquier intervención terapéutica o de investigación. Esta plataforma no almacena ni procesa PII ni PHI.

---

## 🔬 Sobre el Proyecto

Los microARNs (miRNAs) son reguladores post-transcripcionales que controlan la expresión de redes génicas complejas mediante silenciamiento dirigido. Identificar qué genes son **regulados simultáneamente por múltiples miRNAs** es fundamental para descubrir nodos críticos en patologías como cáncer, enfermedades cardiovasculares, neurodegeneración y desórdenes metabólicos.

**KENRYU** automatiza el flujo completo de descubrimiento en una sola plataforma:

| Paso | Acción | Fuentes |
|:----:|--------|---------|
| **1** | 🔗 **Integra** predicciones termodinámicas + validación experimental | TargetScan · miRTarBase |
| **2** | 🎯 **Identifica** la intersección Venn dinámica de genes core regulados | DB local + Harmonizome |
| **3** | 🧬 **Enriquece** las dianas funcionalmente con algoritmo de balanceo | KEGG · Reactome · WikiPathways · GO |
| **4** | 📡 **Investiga** cada gen core en 4 fuentes en paralelo | PubMed · OMIM · ClinVar · ClinicalTrials |
| **5** | 📄 **Genera** informe académico editable con bibliografía Vancouver | PDF · Markdown ZIP · TXT |

> A diferencia de pipelines tradicionales, KENRYU usa una **cascada de búsqueda con fallback** (estricto → ampliado → mínimo) y **traducción de términos al inglés en tiempo real** para superar las limitaciones de PubMed con consultas en español. Todo el flujo está optimizado para **Hugging Face Spaces**, con manejo robusto de rate-limits de NCBI eUtils.

<details>
<summary><b>🔍 PASO 02 — Recopilación multifuente (Haz clic para desplegar)</b></summary>

> **El motor:** Consultas en paralelo a bases de datos de alta fiabilidad.
- **TargetScan 8.0:** Predicciones termodinámicas de unión (Base de datos local).
- **miRTarBase 9.0:** Validación experimental de referencia (*gold-standard*) desde el índice local oficial (nivel de evidencia fuerte/débil + PMID por interacción); el GMT de Harmonizome se descarga bajo demanda como respaldo.
</details>

<details>

- **Modo estricto:** Solo genes comunes a TODOS los miARN.
- **N-1 / N-2:** Consenso robusto para hallazgos más amplios.
</details>

<br/>

| Análisis de rutas | Evidencia multifuente | Resultado profesional |

<details>
<summary><b>📊 PASO 04 — Enriquecimiento funcional (Haz clic para desplegar)</b></summary>

</details>

> **La evidencia:** Consolidación de datos científicos del mundo real.
- Consultas en tiempo real a **ClinVar** (variantes) y **OMIM** (trastornos).
- Integración con **ClinicalTrials.gov** para obtener información relevante de investigaciones en humanos.
</details>

- **Multiformato:** Exportación a PDF, ZIP en Markdown (con recursos) o TXT sin formato.

## 🧩 Características Principales

### 🔬 Análisis Bioinformático

- **Convergencia dinámica** — Intersección Venn de N miRNAs, sin límite hardcoded en el número de genes core
- **Enriquecimiento funcional balanceado** — algoritmo de equidad entre KEGG, Reactome, WikiPathways y GO Biological Process
- **Volcano plot · Diagrama Venn · Interactoma STRING-DB** — generados al vuelo por cada análisis

### 📡 Investigación Multi-fuente

| Fuente | Qué aporta |
|--------|-----------|
| **PubMed** | Artículos científicos por gen + contexto biológico, filtrados por año con cascada de fallback |
| **OMIM** | Catálogo Mendelian Inheritance in Man — enfermedades hereditarias asociadas |
| **ClinVar** | Conteo de variantes patogénicas / probablemente patogénicas reportadas |
| **ClinicalTrials.gov** | Ensayos clínicos activos donde el símbolo del gen aparece en el título |

### ⚡ Robustez y Rendimiento

- **Reintentos 429-aware** — manejo automático de rate-limits de NCBI eUtils con backoff exponencial
- **Cache persistente** — `local_db/analysis_cache.json` almacena traducciones, resultados PubMed y enriquecimiento entre sesiones
- **Mapeo ES→EN** — traduce automáticamente términos biológicos de presets en español para queries PubMed efectivas
- **Cascada de filtros** — estricto → ventana de años ampliada → mínimo, con fallback progresivo

### 📄 Generación de Informes

- **Editor A4 profesional** — vista previa WYSIWYG con paginación inteligente por medición de altura
- **Bibliografía estilo Vancouver** — `[N] Autores. Título. Revista. Año. PMID: X. URL`
- **Citas multi-tipo** — PMID / OMIM / ClinVar / NCT con identificador correcto por fuente
- **Exportación PDF** — vía `window.print()` con CSS `@media print` optimizado y footer anclado en cada hoja A4
- **Exportación Markdown ZIP** — `Reporte.md` + carpeta `/assets/` con PNGs separados + `README.md` — compatible con Pandoc / Obsidian / VSCode

## 📦 Instalación

### Requisitos

- Python 3.11+
- pip
- Docker *(opcional — para despliegue en contenedor)*

### Instalación Local

```bash
# 1. Clonar el repositorio
git clone https://github.com/abrangel/Kenryu.git
cd Kenryu

# 2. Crear entorno virtual (recomendado)
python3.11 -m venv venv
source venv/bin/activate      # Linux / macOS
# venv\Scripts\activate       # Windows

# 3. Instalar dependencias
pip install -r requirements.txt

# 4. Iniciar el servidor
uvicorn kenryu_engine:app --host 0.0.0.0 --port 7860 --reload

# 5. Abrir en navegador → http://localhost:7860
```

### Despliegue con Docker

```bash
docker build -t kenryu .
docker run -p 7860:7860 -v $(pwd)/local_db:/app/local_db kenryu
```

> El volumen `local_db` persiste el cache de análisis entre reinicios del contenedor.

### Despliegue en Hugging Face Spaces

El repo está listo para HF Spaces — el Dockerfile expone el puerto `7860` y monta `local_db` para cache persistente. Solo es necesario conectar el Space a este repositorio de GitHub.

## 🚀 Uso

### Vía Interfaz Web

1. Abrir el [Space en producción](https://huggingface.co/spaces/Kenryu007/Bioinformatica) o `http://localhost:7860`
2. Ingresar miRNAs separados por comas: `hsa-miR-33a-5p, hsa-miR-144-3p, hsa-miR-758-3p`
3. Seleccionar año de corte *(filtro de antigüedad de evidencia PubMed)*
4. Seleccionar modo de consenso *(Estricto / N-1 / N-2)*
5. Click en **Ejecutar**

### Vía API REST

```bash
curl -X POST "http://localhost:7860/api/v1/analyze" \
  -H "Content-Type: application/json" \
  -d '{
    "mirnas": ["hsa-miR-33a-5p", "hsa-miR-144-3p", "hsa-miR-758-3p"],
    "years": 10,
    "mode": "strict"
  }'
```

## 📖 Cómo usar y citar

**Uso.** Interfaz web, API REST (`/api/v1`, esquema OpenAPI en `/docs`)
o CLI (`kenryu panel.txt --offline --out results/`). Cada análisis
devuelve un manifiesto de ejecución (versión del motor, commit,
versiones de datos, parámetros, semillas, comando para repetir) —
cita la versión que usaste.

**Cita.** Si usas KENRYU, cita el registro de Zenodo. El DOI conceptual
siempre resuelve a la última versión:
https://doi.org/10.5281/zenodo.20564688 — Manzo Carvajal, Cesar Abrahan.
*KENRYU: A Platform for Convergent microRNA Target Analysis and
Multi-Source Evidence Integration.* Zenodo. El DOI de la versión que
usaste está en la insignia de arriba y en las notas del release.
El artículo JOSS está en preparación; la evidencia de validación
está en `docs/validation/`.

**Reporta un problema o pide una función.** Abre un issue con las
plantillas de `.github/ISSUE_TEMPLATE/`: un reporte de error (panel,
esperado vs observado, versión/commit del manifiesto) o una solicitud
de función. Los casos de uso reales y los issues reales son como
mejora la herramienta.

## ✅ Validación en Vivo

KENRYU ha sido validado en vivo contra el Space desplegado (`POST /api/v1/analyze`, `years: 10`, `mode: strict`) con tres paneles independientes de microARNs. Cada ejecución se realizó de extremo a extremo a través de la API pública y reprodujo el núcleo convergente esperado.

| Panel | microARNs | Núcleo Strict | Resultado |

## ⚠️ Limitaciones conocidas

- **miRTarBase es ahora el índice oficial 9.0, no el snapshot de Harmonizome.** El motor carga `local_db/mirtarbase_official.json.gz` (396.758 pares miRNA–gen con nivel de evidencia fuerte/débil, PMID y experimento por interacción), construido desde el `hsa_MTI.xlsx` oficial con `build_mirtarbase_official.py`. El snapshot antiguo se descarga bajo demanda como respaldo cuando el índice oficial no existe. Cada gen del dossier lleva su nivel de evidencia (fuerte / débil / solo predicho) con sus PMIDs. El índice es un dato de ejecución, no se sube al repo: para reproducirlo, descarga `hsa_MTI.xlsx` desde la página oficial de miRTarBase y ejecuta el constructor (ver `DATA_LICENSES.md`). Sin el índice oficial el servicio corre en modo legacy: la evidencia "legacy" queda en "media" como máximo (nunca llega a "alta") y la respuesta del análisis trae un aviso visible con el paso exacto para construir el índice.
- **Fondo de enriquecimiento (ruta local): desde v1.54, el universo de TargetScan** — todos los genes con algún sitio predicho por TargetScan (13.035 humanos), intersecado por biblioteca con los genes de cada GMT. La ruta viva de Enrichr usa el fondo propio de Enrichr (su API no admite un fondo personalizado). Cada término de enriquecimiento lleva un valor de especificidad: la fracción de 100 listas aleatorias de genes del mismo tamaño, extraídas del universo de TargetScan, en las que el término aparece por azar (1,0 = genérico; 0,0 = específico; un valor de 0 se muestra como "<1%"). Calibración con paneles aleatorios (`validate_random_panels.py`): ver `paper.md`.
- **KEGG no se redistribuye en este repositorio** (licencia: Kanehisa Labs prohíbe reempaquetar KEGG sin acuerdo — ver `DATA_LICENSES.md`). Desde v1.48 el actualizador descarga la biblioteca KEGG_2021_Human de Enrichr bajo demanda, solo para uso local, así que el enriquecimiento con KEGG funciona también offline una vez descargado; el archivo nunca se sube al repo. El enriquecimiento con KEGG también está disponible en vivo vía Enrichr.
- **Mapeo de alias HGNC desde v1.59.** Los símbolos génicos se mapean a los símbolos actuales de HGNC al cargar (`local_db/hgnc_symbol_map.json`, 538 entradas, conjunto completo de HGNC, CC0): un gen renombrado ahora coincide en TargetScan, las bibliotecas GMT y las APIs vivas. Los genes ambiguos nunca se mapean; el universo TargetScan queda en 12.985 símbolos distintos tras el mapeo. La búsqueda inversa no distingue mayúsculas desde v1.47. Los archivos FASTA locales de miRBase (`local_db/mirbase_*.fa`, 14 MB) los descarga el actualizador pero no se usan para validar nombres; quedan en el repositorio como datos gestionados por el actualizador.
