# Comparison protocol: 10 panels, 4 tasks, by hand

Purpose: compare KENRYU against DIANA-miRPath v4.0, miRPathDB 2027,
miRNet, miRWalk, miEAA and multiMiR on four measurable tasks, and
report only what can be reproduced. No bulk scraping, no automated
hammering of web UIs — each web tool is run by hand, a few panels at
a time, under its own terms of use. If a tool cannot do a task,
record "not applicable" with the reason, never a zero.

## The 10 panels

Fixed before any tool is run (`docs/validation/comparison-panels.json`,
generated by `scripts/generate_comparison_panels.py`):

- **Reference (3):** lipid (thesis, 5 miRNAs), cancer (3 miRNAs),
  control (miR-375, miR-29a-3p, miR-21-5p, 3 miRNAs).
- **Random (7):** R1–R7, fixed seeds 101–107, sizes 2, 3, 5, 5, 5,
  8, 10; one miRNA per TargetScan family, so each panel has as many
  effective seed families as names.

## The 4 tasks

1. **False positives on random panels.** Run the 7 random panels
   (the 3 reference panels are controls, not counted). For each
   tool, record the share of random panels with at least one term
   at the tool's own significance criterion — and record that
   criterion exactly as the tool states it (adjusted p < 0.05,
   FDR, or whatever it uses). Record the background/universe
   setting chosen; if the tool offers no choice, say so.
2. **Recovery of strong targets (sensitivity).** Reference set: the
   known strong (Functional MTI) targets in miRTarBase v9.0
   (`docs/validation/strong-controls.md`; 754 pairs, 54% recovered
   by KENRYU's TargetScan route). For each tool, run the same 10
   miRNAs (the 5 lipid + miR-21-5p, miR-155-5p, let-7a-5p,
   miR-375, miR-29a-3p) and count how many of their known strong
   targets the tool returns. Metric: recall = found / known.
   If a web tool makes 10 miRNAs impractical by hand, run 5 (the
   lipid panel) and say so.
3. **Reproducibility.** Run the lipid panel twice, on different
   days. Record whether the results are identical (gene lists and
   term lists) and whether the tool gives a version record for the
   run (software version, data versions, parameters, seed). Binary
   answer plus the record itself.
4. **Offline.** Can the tool run with no network? Record how
   (local install, Docker image, R package) or "no". KENRYU: yes
   (offline mode, local TargetScan + miRTarBase index). multiMiR:
   yes (R package). DIANA-miRPath, miRPathDB, miRNet, miRWalk,
   miEAA: web only, as far as their articles and sites show.

## Recording rules

- One run folder per tool per date:
  `docs/validation/comparison-runs/<tool>/<YYYY-MM-DD>/` with the
  tool's raw output (downloaded tables, screenshots, or a pasted
  transcript), the parameters used, and the tool version as shown
  on the day.
- The results table lives in `docs/comparison.md` (the "Measured
  comparison" section): one row per tool, one column per task, with
  the run folder linked. A cell with no run folder is empty, not
  zero.
- A result is only reported if it can be reproduced from the run
  folder. The paper cites the protocol, not the other tools'
  marketing pages.

## KENRYU baseline (already run)

`docs/validation/comparison-kenryu-baseline.json`, local engine,
Strict mode, offline, 20 November 2026:

- False positives: **0 of 7 random panels** with a significant
  local term (0 of 10 including the reference panels). The random
  panels converge on 0–162 genes (R1: 162 genes from 2 miRNAs;
  R3, R6, R7: 0 genes), and none yields a term.
- Sensitivity: 54% of strong targets recovered (404/754;
  `docs/validation/strong-controls.md`).
- Reproducibility: the same panel gives the same result by API
  and by CLI, on the local engine and on the Space (v1.57, seed
  2547548954, identical p); the execution manifest records version,
  commit, data versions, parameters and seeds.
- Offline: yes.
